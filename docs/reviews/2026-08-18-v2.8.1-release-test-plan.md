# What to test before shipping v2.8.1

Ordered by risk, not by feature. The first section is the part that would actually stop a release; the
rest is confirmation that the seventeen changelog fixes do what they say.

Nothing in this release has been run on this machine - a locomotive database has been bound to the CS2
port throughout, so every model-based test class skipped. **A green suite run in NetBeans is the first
item, and the tag comes after it, not before.**

---

## 0. The suite, in NetBeans

Everything below assumes this passed. Two things to watch for, because both have bitten this week:

- A class reporting **`Failures: 0, Skips: N` with a Configuration Failure did not run.** That is not a
  pass. `testAutonomyPathValidation` and `testLayoutTiles` ask `init()` for the UI and skip under a
  headless runner; they must actually execute.
- `testAutoDetect` fails 3/3 for want of a Central Station at 192.168.50.25. Environmental, not a
  regression.

## 1. Highest risk: the four fixes made today, none of them exercised

These landed after the release review and touch the autonomy driving path. They are the reason not to
tag on a compile.

### 1a. The semi-autonomous stall (MB-B1) - **the one to test hardest**

The path search moved off the event thread, and the timetable-start read moved with it.

1. Load a graph, **do not** start full autonomy. Place two or more locomotives.
2. Double-click a path for train A. While A is having its switches thrown, double-click a path for
   train B, and click around the interface - switch tabs, drag a slider.
3. **Expected:** the interface stays responsive throughout. Before this fix it froze for the length of
   A's configuration, up to about two seconds per path.
4. **Watch for the regression this could introduce:** each locomotive panel's path list is now filled
   in a moment after the panel appears. Confirm the lists are correct and complete once settled, that
   the `*` timetable marker still appears on the right station, and - most important - that
   double-clicking a path still starts **that** path and not another. The dispatch index is resolved
   against the list the user saw, and that is exactly what `UH-B5` fixed.

### 1b. The callback door (MB-C1)

Every callback now fires through one guarded call rather than the dispatch site alone.

- Run autonomy with the graph window **open** for a while, several trains, several arrivals. Nothing
  should behave differently; this is a guard, so success is "no change".
- The failure it prevents is a train stopping mid-block with its track locked and never being
  dispatched again. If any locomotive silently stops being dispatched, capture the log.

### 1c. Two route editors (MB-C2)

- **Double-click** the Add Route button quickly. Expected: one editor, and a message pointing at it -
  never two windows.
- Same from the edit path: double-click a route in the list.
- Then capture commands into the editor and confirm they land in the window you are looking at.

### 1d. The dead key (MB-C3)

- Nothing to test. It was an unreachable message; the deletion is cosmetic. Included only so the list
  is complete.

## 2. The seventeen changelog fixes

Roughly in order of how much a failure would hurt.

**Autonomy**

- Place a locomotive on the graph **without choosing a speed**, then start autonomy. It must be
  dispatched rather than waiting forever, and autonomy must start without a graph reload.
- With a **short** list of available paths, double-click the empty space below the list. Nothing should
  start.
- Correct the computer clock **backwards** (or let a time sync do it), then trigger a feedback sensor.
  It must still register.

**Locomotives**

- With trains running, press **Go** on the Central Station, then check the statistics tab: accumulated
  running time must not reset. Repeat by clicking a track diagram accessory, which turns power on first.
- Try to add a locomotive at an address **one** existing locomotive already uses. It must be reported as
  taken.

**Routes**

- Create a route whose condition names locomotive X. **Rename X.** The route must still fire.
- Capture commands into a route that drives **two** locomotives: set a speed for one, a function for the
  other, then capture a turnout. Nothing already captured may disappear, and saving must keep it all.
- Import a routes file containing **two routes with the same name**. The rejected one must not keep
  triggering from its s88 - previously it ran invisibly until restart.
- Open the bulk enable/disable prompt and **cancel** it. The list must refresh and nothing change.
- Try to rename a locomotive to a name containing a **comma or bracket**, and to use such a locomotive
  in a route condition. Both must be refused.

**Track diagrams**

- Rename a page from `Main` to `MAIN` - same name, different capitalization. The page must survive.
- Click a tile in the editor without dragging, then close. It must not ask whether to save.
- Click an item in the component **palette** rather than dragging it onto the diagram. No error.

**Central Station sync**

- Start TrainControl while the Central Station is reachable but make the **initial sync fail**, then
  change a locomotive's speed at the Central Station. TrainControl must still show it.
- Edit a locomotive while a **backup or automatic sync** runs. The database must be saved.

## 3. Known and accepted, not to be treated as new faults

- **Backport C1:** a crash between the two moves of a case-only page rename can leave the page as
  `<name>.cs2.renaming`. Window is milliseconds, nothing is lost, and the file is recoverable by hand.
- **Backport C3:** a 0-speed locomotive in a **parallel** timetable retries in an unbounded paced loop.
- The `C1-C29` low-severity findings of the whole-project review are open by choice. At least one of
  them is already fixed and never marked, so treat that table as unverified rather than as work.

---

## 4. The tag

After a green suite and section 1, mark the known-good commit and tag `v2_8_1`. Not before: the four
fixes in section 1 are in the autonomy driving path and have been compiled, not run.
