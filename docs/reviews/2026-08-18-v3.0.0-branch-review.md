## B - Medium

### GR-B1. A home on a split square becomes a home on an arbitrary copy

[AutonomyBuilder.java:764-794](../../src/org/traincontrol/automationui/AutonomyBuilder.java) (the
extras loop: `loc` lands on exactly one copy via `placementCopy`; `home` is not in any skip list, so
it is emitted onto **every** copy of a split square), against
[Layout.java:584-616](../../src/org/traincontrol/automation/Layout.java) (`rebuildHomeStations`: a
second Point claiming the same locomotive is stripped - `warnHomeLocomotiveAssignedTwice`, whose
comment says "only a hand-edited file reaches here". The builder now generates that shape).

The trace, concrete:

1. Mark a station square "trains may turn round here" - which is precisely what a berth or a stub
   platform gets - and author a home on it. The square is emitted as plain and turning copies (per
   arrival side), each carrying `home`.
2. `parseAuto` sets `homeLoc` on each; `rebuildHomeStations` keeps the **first in parse order** (the
   plain copy of the enum-first arrival side - deterministic, but meaningless to the user) and
   strips every other copy, logging one "assigned twice, hand-edited file" warning per copy, on
   **every load**, for a file no hand ever edited.
3. Return Home now targets that one copy, i.e. one specific arrival side. Where the railway happens
   to allow that approach, everything works and only the log lies. Where it does not - one-way
   running toward the other arm - the plan is refused for a home that looks perfectly good on the
   diagram, and nothing names the split as the reason.
4. The sharpest case: a **must-turn** square with two approaches emits only turning copies, and a
   turning station copy is a **terminus**. The home therefore lands on a terminus copy, and
   `HomeStaging.canRest` refuses a terminus for a non-reversible locomotive - so Return Home
   reports IMPOSSIBLE, naming the locomotive, for an authored home on the exact kind of square
   (a berth every train must back out of) the feature exists to serve.

The authored data itself survives - the companion store keys `home` by tile, and the parse-time
strip touches only the running layout - so this is wrong behaviour and log noise, not loss: B.

Verified absent everywhere it could have been caught: `build()`'s skip lists, the fifteen
`AutonomyChecks` (none mentions homes), and the test suite (the only home tests cover legacy import
into extras; nothing walks a home through a split square into `rebuildHomeStations`).

**Fix shape:** the builder already solves this exact problem for the other per-square singleton -
`LOCOMOTIVE` lands on one copy via `placementCopy`. The minimal fix is the same treatment for
`home`: emit it on one copy, preferring a plain, arrival-allowed, non-terminus copy when one
exists (and the turning copy only when nothing else is emitted, as on a must-turn stub). A check
naming squares where the home had to land on a terminus copy - "this home requires a reversible
locomotive" - would make the residue visible instead of silent. The deeper alternative - teaching
`getHomeStation`/`canRest` that a home on any copy of a `block` is satisfied by the block - is more
faithful to what a home means, but it widens a shared primitive that staging, capture and the
planner all read, and that trade is the author's to price, not this review's to make silently.

## C - Low

### GR-C1. The route that needs one switch two ways vanishes without a word

[GraphReducer.java:846](../../src/org/traincontrol/automationui/GraphReducer.java) - a branch whose
`collectCommands` conflicts with the path so far is `continue`d, and nothing is recorded. The rule
itself is right - it is the model's own conflicting-commands refusal, applied early - but every
other way a run can fail to become an edge (parallel route, self-loop, double-curve ambiguity)
leaves a warning behind, and this one does not. A layout whose only path between two sensors
re-crosses a switch in the other position - a wye or a folded loop without an intermediate sensor -
just quietly lacks the edge, and the user's first sight of it is a connectivity test saying no.
Rare by construction (a sensor between the two crossings dissolves it), which is why this is C.

### GR-C2. Portals have no direction, and the setting that suggests otherwise would not work

[TileGraph.java:550-567](../../src/org/traincontrol/automationui/TileGraph.java) - the portal
branch of `exits()` offers the jump unconditionally (no `directionAllows` consultation), under the
synthetic `PORTAL_ROUTE (0,-1)`; `getRoutes` lists the tile's stub route as `(0,0)`. So a direction
authored against anything `getRoutes` returns for a link tile does not affect traversal, and one-way
cross-page running cannot be expressed at all - a run through a link is bidirectional whatever the
user does. Today this is an expressiveness gap plus a latent id mismatch rather than wrong
behaviour; it becomes wrong behaviour the day the direction UI offers a link's route and appears to
accept the setting.

### GR-C3. A protecting signal that stops existing protects nothing, silently

[Layout.java](../../src/org/traincontrol/automation/Layout.java) - `parseAuto` accepts any string
for `protectingSignal`, and `refreshProtectingSignal` returns quietly when
`getAccessoryByName` misses (correct at refresh time - a placement must not fail over a signal).
But nothing ever says it: not parse, not the checks, not the session. Pairings are stored by
canonical accessory name so a rename cannot orphan them, which bounds this to a signal deleted from
the database or a configuration imported against a different layout - and in exactly those cases
the operator believes a platform is protected and it is not. One check - "this pairing names an
accessory the layout does not have" - closes it.

## GR-D1. The derivation core, verified

Read line by line, unanchored, with each claim checked in the enforcing method:

- **The port map** (`TilePorts`): the rotation law matches `getImage`'s `(4 - orientation)` quarter
  turns; state-replacing switch semantics with no toe concept; both-addresses-always-commanded on
  the three-way; the double slip commanding in both states; defective turnouts as hardware-directed
  trailing routes that also suppress the base-to-forks default (the AND that would otherwise seal
  the tile is reasoned in `defaultDirection`); `deriveToe` derived from the table so it cannot
  drift. Consistent with the author-verified port-map sheet.
- **Trace continuity**: the `(square, entry side)` walk state is uniform across
  `findUndirectedPath`, the reducer's circle guard, `findPath`/`reachableTiles`, and the builder's
  `leavesBy` - the double-curve confinement is enforced identically at emission and at search,
  which is what keeps the editor's "impossible" and the built graph's offerings in agreement.
- **Lock derivation**: intersecting `getPath()` with endpoints excluded is correct **because** of
  the division of labour - a sensor tile is an edge endpoint and an intermediate of nothing
  (validated on the real layout: 54 sensor tiles, 259 intermediate, none in both), so endpoint
  conflicts belong to point/block occupancy and lock edges to the track between. The overpass
  per-route exception matches the port map's one grade-separation. The portal claim ("a tunnel and
  its far end are one location") holds de facto: both ends always appear in a crossing edge's path,
  so sharing follows without the special case the comment implies.
- **The head-on the split makes nameless is guarded.** Split copies break the model's literal
  opposite-name check, and the reducer deliberately exempts exact reverse pairs from locking - so
  square-wide occupancy is the only guard, and it holds: `Edge.isOccupied` asks
  `getBlockLocomotive` by default, `block` is emitted on every split square, survives `toJSON` and
  `parseAuto`, and with `atomicRoutes` (the default; the builder emits nothing to change it) a
  start point keeps its locomotive until the path completes. Traced for dispatch-vs-parked,
  dispatch-vs-mid-run, and simultaneous opposite dispatches; refused in each case at the block.
- **`reserve()` vs `setLocomotive`**: the sweep lives only in placement, reservation never sweeps,
  hand placement alone calls `clearBlockExcept` (and logs the displacement), and
  `handleMisconfiguredPath` re-reserves the start against the loop-path corner. The lock-ordering
  rationale for the unsynchronized sweep is stated and holds - the placement-single-writer
  invariant it rests on is written down at the site.
- **`isLockHeld`** (a lock edge asks "held", not "parked beyond"): sound for derived graphs, where
  locks are symmetric by construction; the record's own post-fix `B1` already withdrew the symmetry
  claim for hand-authored graphs with measured data (104/118, 290/312 asymmetric), and the residual
  exposure is bounded to session-only legacy imports. Concur with fix-stands.
- **`refreshProtectingSignal`**: the memo keyed by accessory (not Point) closes the stale-memo
  green-under-a-train fault, covers two stations paired to one signal, and commands only on change.
  Observation, recorded not filed: a signal thrown by an outside actor (a route, the keyboard)
  while its aspect memo already matches is not re-corrected until the next occupancy transition -
  the price of command-on-change, and no worse than any other externally-thrown accessory.
- **Staging alignment**: removing the planner's lock-edge rule tracks the runtime's narrowing and
  is additionally justified by one-train-at-a-time staging; `canEnter`'s per-Point occupancy is
  documented as agreeing with the block rule "by coincidence rather than by construction" - an
  honest note this review endorses keeping until GR-B1's disposition decides whether homes (and
  therefore staging targets) become block-aware.
- **The callback and dispatch armour**: `fireCallback` is now the single guarded door for all
  callback sites, and `runLocomotive`/timetable dispatch guard `executePath` - the branch-side
  closure of `MB-C1`'s whole class, done at the root rather than per site.
- **The ground-truth suite** (`testAutonomyGroundTruth` + the pinned v2.8.1 station-paths file) is
  a change detector, not an oracle, and says so itself in so many words - the right claim for what
  it is, and the reason a changed answer must be argued rather than regenerated.

## Verdict, and the tagging step

The new autonomy graph setup is **sound in its core**: the port map, the trace, the reduction, the
split, and the block occupancy that makes the split safe were each verified independently and came
back either correct or already ledgered. The one open B (GR-B1) sits in the headline feature's data
path - homes are what Return Home runs on - and its minimal fix is the pattern the builder already
uses for `loc`, plus one check; the three Cs are small and two of them are single-check closures.

Per the process: no tag was created. The branch's known-good convention
(`autonomy-clean-2026-08-18`) would want GR-B1 dispositioned, the Cs decided, and a green suite run
in NetBeans before the next known-good mark - and the post-fix round's open B-list is the other
half of that gate, already recorded there.
