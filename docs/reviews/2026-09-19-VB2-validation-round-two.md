### VB2-B1 - the exit asks the layout editor twice

**Where.** `src/org/traincontrol/gui/TrainControlUI.java`. `WindowClosed` (`:19195`) still opens with OB-070's block:

```java

}
```

**What the second question does.** `LayoutEditor.maySettleBeforeExit` (`LayoutEditor.java:5994`) -> `settleUnsavedWork` (`:6071-6136`), which decides `unsaved` from `canUndo()` in track mode (`:6073`; `canUndo` is `!previousLayoutComponents.isEmpty()`, `:5495`) and resets `settledByDiscarding = false` at `:6076` before asking.

The undo stack is untouched, so the second call asks again. Discard again: fine. **Save: the work the operator just chose to discard is written to disk** (`saveBeforeLeaving` `:6448-6469`), and `settledByDiscarding` is now false, so nothing undoes it. Cancel: the exit is refused with the editor open and the first Discard forgotten - as after a plain Cancel, which is acceptable.
- *Track mode, first answer Save.* `saveChanges` does not clear the undo stack - the only `previousLayoutComponents.clear()` is the page-switch teardown at `:6339` - so `canUndo()` is still true and the operator is asked to Save/Discard/Cancel work that is already saved.
