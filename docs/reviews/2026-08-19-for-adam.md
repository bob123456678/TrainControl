# What to look at when you're back

Twenty-eight numbered items in five stages, in the order I would do them. Stage A is the only one that
cannot wait; the rest can be picked up whenever.

Roughly: A 35 min · B 20 min · C 20 min · D 10 min · E 35 min.

---

## Stage A — Run it (35 min)

Nothing below substitutes for this. Open a layout, `Autonomy` → `Add a Configuration...`, place two
trains, press start.

**1. Watch trains run for five minutes.** Nothing should stop silently or take a route you would not
have chosen.

**2. Press Graceful Stop.** Everything should halt, and the buttons should come back promptly — not
instantly, but within a train's arrival. *This changed: see item 21.*

**3. Hover "No available paths"** on a locomotive that cannot move. You should get a list of stations
and, for each, the reason. This is new and it is the feature I would most like your read on.

**4. Open the setup editor → "Why is it not moving?"** and click a square with a train on it. Routes
it *could* take are drawn on the track; reasons for the rest are listed underneath. With unsaved edits
it says so; without, it stays quiet.

**5. Multi-select.** Shift-click a few squares; shift-drag a box; right-click → Selection → *Select
This Whole Row*. Then drag the group, Fill it, Delete it. **Undo after each — every one should be a
single step.**

**6. The size controls.** Right-click → Diagram → the `+` and `−` pair. Grow once, shrink once: you
should get back exactly what you started with. `−` refuses if the edges hold track.

**7. The new route editor.** Routes menu → the new editor. **Open an existing route, change nothing,
save. Then check its delays and decoder types survived.** Two separate data-loss bugs lived precisely
there.

**8. Build a condition by hand.** Add a condition, change its Kind to Accessory, set Protocol to DCC,
save. This path was completely stuck until the last review found it.

**9. Capture.** Tick capture in the new editor, throw some switches, and watch them appear. Then
switch the destination to *Into conditions* and do it again.

**10. Export a diagram.** `Layout` → `Save This Diagram as a Picture...` — the page you are looking
at, no question asked. (`Save Diagram as a Picture...` below it still asks, for any other page.)

### The four from the eighth review that are worth a minute each

These are new fixes to old code, and they are all quick to try.

**11. Turn a standing train round.** Right-click a station with a train on it → Facing → the other
direction. **Have a *different* locomotive selected on the keyboard when you do it.** Until today
this moved the selected one onto that platform instead, in the running layout and the saved
configuration both — and did nothing at all if none was selected.

**12. Right-click a sensor with the autonomy overlay switched off.** Nothing should happen. It used
to silently flip the sensor's occupancy, which during a run is exactly the input the layout reacts
to.

**13. Press Start twice, quickly.** One run should begin. There are three places to press it — the
button, the diagram strip, the station right-click menu — and any two of them in quick succession
used to start two.

**14. Try to tick a page out of autonomy while trains are running.** It should refuse. Then stop, tick
one out, and confirm the railway agrees with the diagram — previously the interface said a page was
out while trains carried on being routed to its stations.

## Stage B — Six decisions only you can make (20 min)

**15. Is it time for Phase 2?** Deleting the graph window, the GraphStream jars, the `GRAPH_*` prefs.
The plan gates this on real use of your layout, not on my judgement.
→ `2026-08-19-phase-plan-status.md`

**16. The diagram `+` does not add a row at the top**, only right and bottom, so `+` and `−` are exact
mirrors. Doing it as you asked means rewriting every key the companion store holds for that page —
stations, signals, arrivals, homes and captions are all keyed by square.
→ `LayoutEditor.growEdges` javadoc

**17. `TEST_CS2_ADDRESS`** is a `public static volatile` test seam read by production code. I kept it;
the tightening a reviewer suggested is a larger change than the risk.
→ work log, first run

**18. Signal pairings and barred arrivals are invisible in bulk** — auditable only one station at a
time. Acceptable for a first release?
→ `2026-08-19-completeness-and-3.1.0.md`

**19. The `maxActiveTrains` cap can be exceeded.** Two trains taking *disjoint* paths can both pass
the check before either registers, so a cap of one can run two. Track locking holds throughout — this
exceeds a preference, it does not risk a collision. Closing it means reordering the path-locking
protocol under a running layout, which I would not do without you watching. **Deferred on purpose.**
→ `2026-08-19-eighth-review.md`, "Deliberately deferred"

**20. The locomotive wait loops busy-spin if a thread is ever interrupted.** Nothing interrupts them
today, so it is latent. I know the fix and it is small, but it touches six blocking waits in the
train-control path and an interruption cannot be tested end-to-end here. **Deferred on purpose** — say
the word and it takes ten minutes.
→ same

## Stage D — Know about, nothing to do (10 min)

**22. A graceful stop now takes a moment longer to report itself finished** — and is telling the truth
for the first time. `isRunning()` was blind to a locomotive between deciding where to go and departing,
so the layout called itself stopped while a train was one instruction from moving, and every "is it
safe to edit" check believed it. If it feels *slow* rather than a moment, tell me.

**23. A Stop pressed while a train is mid-sleep still waits that sleep out** — bounded by your delay
setting, or 30 s for the yield wait. Much smaller than the indefinite hang it replaced, not zero.
Making it zero means interruptible waits everywhere.

**24. Two long-standing faults could take the power off a healthy layout**, and both are fixed. One
lost ping response used to end the keepalive for the whole session — "lost connection" for ever, and
under autonomy the latency cutoff firing every five seconds, including five seconds after you turned
the power back on. Separately, any short system frame from anything else on the CAN bus read as an
emergency stop. If either has ever happened to you and you put it down to the layout, it was this.

**25. If TrainControl ever failed to read `LocDB.data` at startup, it used to save an empty one over
it on the way out.** Now the unreadable file is copied aside first and the log says where. Your
database is fine — this is about the next time.

**26. Nine entries removed from the 3.0.0 changelog** as bugs that only ever existed on this branch.
The judgement call is *"trains stopped moving even though routes were available"*.

**27. `Automation.md` is now the user guide**; the JSON and API reference moved to `AutomationAPI.md`.
**Removed from the diagram editor:** paste-entire-row, paste-entire-column, the four
shift-the-whole-diagram items, and `Shift+C`/`Shift+R` — multi-select replaces them. **The condition
editor offers only accessory and feedback kinds**; others produce a permanently false condition, and
an existing auto-locomotive condition is preserved read-only.

### What I could not test

Your Central Station. `testRouteReachesTheRails` now runs routes and checks the accessories — a DCC
command moves the DCC switch while its MM2 twin at the same address stays put, and delays are timed
rather than inspected — and reinstating the two original bugs fails three of its four tests.

But that proves a command was *formed and dispatched* correctly, not that hardware obeys. One
correction to something I said earlier: `DEBUG_SIMULATE_PACKETS` is not what makes those assertions
work — `setAccessoryState` updates the local state directly, so they hold with or without the echo.
What they really rest on is MM2 and DCC occupying separate UID spaces.
